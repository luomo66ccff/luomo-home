# 两幕转场性能记录 · 2026-10-09

此次继续处理手机从第一幕站台滑到第二幕航图、以及返回站台时的卡顿。基线是上一轮加载优化后的 main `58b4b699f12a63d03c192cccaaa724dd73d0d344`。

## 原因与实现

触摸追踪显示，站台滑出时 CSS、SVG SMIL 和星空 Canvas 仍在运行。浏览器还在 scrollY 约 247px、1242px 时提前展开 `operations`、`projects`；这两块距离视口下方仍有约 1,300px，却分别产生了约 234ms、138ms 的冷布局。仅提前展开第二幕 `services` 无改善；暂停场景降低了持续掉帧，预展开屏外内容消除了这两次冷布局。

- 手机触摸和滚动期间，按板块暂停装饰 CSS、SMIL 和 Canvas；手指离开且最后一次滚动超过 200ms 后，继续原来的时间线。持指期间不启动恢复计时器，避免慢设备反复启停。
- 只提前准备 `operations` 和 `projects`，一次处理一个，之间留出渲染帧和 300ms 间隔。优先在开场遮罩内开始；闲时回调最长等待 750ms，防止持续装饰动画使准备任务一直得不到执行。触摸、滚动、隐藏和断点改变会取消尚未执行的准备任务；其他远处板块继续延迟布局。
- 导航进度改为直接更新小轨道的 transform，页面高度和轨道宽度由 ResizeObserver 缓存。手机不再逐帧测量八个板块，桌面高亮由 IntersectionObserver 更新。

## 转场对比

本机生产构建，Windows 无头 Microsoft Edge、390×844、DPR 2、触摸移动模式、深色、正常动效，CDP CPU 6 倍降速，禁用缓存。每个版本三个全新上下文；加载至少 8 秒并等待字体后，执行下行、上行、下行、上行四段输入。每段四次触摸拖动，每次 25 步、每步 15px，名义每步间隔 33.3ms；逐次等待 CDP 输入确认。所有采样均实际跨过两幕交界，下行终点至少 1,000px，上行终点在首幕的 350px 内。

第一轮记录 trace，另外两轮不追踪；表格为三轮中位数。惯性滚动和输入确认耗时会让实际速度、结束位置略有不同，属于同输入序列的浏览器实验室对照。`rAF` 间隔不能直接换算为实体手机屏幕帧率。
